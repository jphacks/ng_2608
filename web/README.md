# スキあらば恋、隙間ないAI

> 追加機能の現在の動作は [CONVERSATION_UPDATE.md](CONVERSATION_UPDATE.md) を参照してください。以下の旧版の「変更後に通知して自動送信」という記述は、送信前の確認・編集・再チェックに置き換わっています。背景変更、14問後の価値観トーク、会話中の相性ヒントも追加しました。

本人が情報の行き先を選べる、AI対話とマッチングのベータ版です。

## 実装した体験
- 基本情報→写真→6分野14問の質問で登録。従来の自由会話は互換用
- 6分野14問の回答に基づく希望の整理（旧3軸は互換用）
- 本人による修正と公開選択。公開前の候補や根拠は端末内のみ
- 公開した質問回答の近さと本人が選んだ大切さによる相性スコア
- 公開プロフィール、相互の関心、マッチ後のチャット、ブロック解除、通報記録
- 写真の端末内読込、範囲指定のモザイク・塗りつぶし・切り抜き、メタデータ除去、加工後の保存・削除
- 普通のチャットはそのまま送信。個人情報・強い言葉の候補だけ自動加工し、変更は任意で確認
- 端末内とAI送信の記録、写真・登録データの削除

## 情報の境界
原文・置換表・元の写真は外部AIに渡しません。マスキングは端末内で始めます。
AIには加工済み文章・目的・選んだ回答履歴・固定指示・出力形式だけを渡します。自動補助は登録時に本人が有効化した場合だけです。
AIの本文はアプリで永続保存・ログ出力せず、Responses APIはstore:falseです。
外部事業者の保存・監視ポリシーは別途適用されます。
通常のチャットでは、検出があった文を加工してから送ります。検出のない文はそのまま送信します。

公開プロフィール・加工後の写真・実ユーザー間の関心や会話・ブロック・通報はD1/R2へ保存します。
AIの利用回数は1人1日60回まで。登録削除ではこの利用回数をリセットしません。

## この段階での限界
- 個人情報検出はルールと辞書であり、完全な匿名化ではありません。
- 写真の自動検出は文字・顔の候補であり、看板の意味や本人の顔を保証するものではありません。
- タイプは心理検査ではなく本人の質問回答を整理したものです。相性スコアはマッチ確率ではありません。
- 年齢は自己申告です。本人確認・年齢証明の審査は未実装です。
- 通報は受付記録のみ。専任の監視や即時対応の運用はありません。
- チャットの開示候補は表示中の直近100件から検出します。履歴全体の特定リスク計算ではありません。
- サイトの公開範囲はSitesで管理します。プロフィールの保存時に閲覧範囲を確認してください。
- AIキーはユーザーが選択した7日間の有効期間です。期限後は再設定が必要です。

## 質問形式への改善: 質問式プロフィールと自動加工

自由会話3回からのタイプ推測を、6分野・14問の選択式質問に置き換えました。
質問と計算は `public/demo/questionnaire.js`、画面との接続は `questionnaire-ui.js` にあります。
回答を根拠にすることで、短い会話からの性格の断定を避けます。心理検査やBig Fiveの測定ではありません。
「落ち込んだときの希望」は支え方の希望であり、感情の安定性を表すものではありません。

相性の基本重みは恋愛スタイル30・ライフスタイル20・コミュニケーション15・理想の関係15・食10・将来10です。
ユーザーは各項目について一致の大切さを選べます。共通の公開回答が7項目かつ3分野以上のときだけ総合点を出します。
スキップ・非公開の回答は計算に含めません。重みは仮の製品ルールで、実証済みの相性やマッチ確率ではありません。
20歳未満には飲酒を希望する選択肢を表示せず、サーバーでも受け付けません。
既存の3軸プロフィールは残しますが、新しいスコアのために14問へ再回答が必要です。

文章は `privacy.js` が自動で一般化します。現在のチャットでは変更がある時だけ通知し、詳細の確認は任意です。
写真はTesseract.jsの文字検出とMediaPipeの顔検出を端末内で行い、自動マスキング案を作ります。
文字候補は隠す案とし、顔は最も大きく写る候補を1つ残す案です。本人の顔と判断する機能ではありません。
見落とし・誤検出があるため、候補の変更と手動補正も残しています。初回のモデル読込は時間がかかります。
画像やOCR結果を外部AIに送信しません。実行ファイルと言語モデルも同一サイトから読み込みます。
ライブラリを入れ直した場合は `node scripts/prepare-vision-assets.mjs` で静的アセットを再作成できます。

## UX改善: 会話を止めないUXとピンクのデザイン

`public/demo/experience.js` と `pink.css` で、基本情報→写真→価値観の質問の登録順序と、新しい画面を実装しています。
氏名は `account_details` に本人用として保存し、一般のプロフィール・一覧・マッチ相手へのAPIには含めません。
年収は任意の金額帯です。初期設定では非公開で、明示的に公開を選んだ場合のみプロフィールへ表示します。
本名・登録年収はAIの文脈へ付加せず、相性の採点にも使いません。

普通のチャットは確認モーダルやAI呼び出しを挟まずに送信します。
`support.js` が個人情報候補や一部の強い言葉・NGワードを検出したときだけ、端末内で言い換えます。
登録時にAI補助を有効にした場合のみ、加工済みメッセージをAIで自然／ユーモアのある表現に整えます。
AIが利用できない場合や出力確認で止まる場合は、端末内の言い換えを使います。原文を代替送信しません。
利用者には変換した時だけ通知し、「変更を見る」で原文と送信後の文を任意に確認できます。
原文を含むこの変更記録はタブ内だけに保持します。自動変換には見落としや意味のずれがあるため、会話の文面は確認可能にしています。

写真の3つの必須チェックを廃止し、通常は登録ボタンだけにしました。
顔が確認できない、複数の顔、文字の写り込み、検出失敗などの候補がある場合だけ注意を表示します。
顔が1つで写り込み候補がないケースも、個人情報が絶対にないと保証するものではありません。
新しい移行は `drizzle/0002_normal_captain_marvel.sql` です。

## 登録フローと会話相性の更新

初回はプロフィール・写真→14問の性格・価値観チェック→3問のAI診断→結果の公開確認→相手探しへ進みます。
`public/demo/journey.js` が画面遷移、`lib/onboarding.mjs` が本人の保存済み進捗を管理します。
AI診断の検証済み最終結果は本人用の `account_details` に保存し、公開を選んだ項目だけを相手へ表示します。
AI診断と結果確認が済むまで相手一覧・関心送信を制限します。公開されたAI診断の希望が比較できる場合、選択式80%・希望の類似20%を使います。

会話相性は `public/demo/conversation-score.js` が、送信済みの直近100件から端末内で更新します。
双方の発言がある場合に80点を起点として共通話題、やりとり、前向きな表現を加点し、80〜98点を表示します。
高めに出る製品上の参考スコアで、恋愛成功率や好意の測定ではありません。生成AIによる会話の解釈でもありません。
会話履歴を外部AIへ送ることなく、相性の点数だけを画面に表示します。
通常送信とAI診断の前処理は、ルールベースの自動加工で利用でき、WebGPUモデルの準備は必須ではありません。
追加移行は `drizzle/0004_open_shard.sql`。公開済み移行の書き換えは行いません。

## スマホ同士で友達と話す

1. 各スマホで公開サイトを開き、それぞれ別のChatGPTアカウントでログインします。同じアカウントの2台は同じ利用者です。
2. それぞれプロフィール・写真・診断を完了します。
3. 「さがす」→「友達を招待する」でリンクをコピーするか、スマホの共有ボタンを使います。
4. 友達がリンクを開いて「この友達とマッチして話す」を押すと、双方に実チャットが作られます。
5. 送った側は「トーク」から友達を選びます。前面表示中は約2秒ごとに更新し、回線復帰・画面に戻った時も再取得します。

招待は24時間・1人用です。期限切れや他の人が使用済みの場合は、新しいリンクを作ります。
通信は公開サイトの認証とD1を通します。同じWi-FiやBluetooth接続は必要ありません。
現時点ではバックグラウンドのプッシュ通知はありません。

`public/demo/friends.js` が招待と同期、`lib/friend-invites.mjs` が認可・期限・1人用の処理を担当します。
追加の移行は `drizzle/0005_dapper_wasp.sql`。招待に登録氏名・年収やメールを付加しません。

## NG発言の扱い

`public/demo/chat-policy.js` をブラウザーとサーバーで共有し、検出した性的な発言・暴言は新規送信を拒否します。
端末内で暴言をやわらげる前に判定し、NG発言を自動変換してそのまま送る動作にはしません。
`message` APIを直接呼んでも `CONTENT_BLOCKED`（422）になり、本文を保存しません。外部AIへの入力・出力も確認します。
全角、ゼロ幅文字、一部の記号・空白混ぜを正規化して確認します。ルールと辞書なので、未登録の言い回しの見落としや誤検出はあります。
過去に保存されたメッセージを削除する変更ではありません。

## 別利用者の画面でローカル確認する

`web/` を作業場所として、2つのターミナルを使います。両方が同じローカルDBを使います。

```sh
KOTONOHA_LOCAL_USER=test-a KOTONOHA_LOCAL_PORT=5173 npm run dev:local
```

```sh
KOTONOHA_LOCAL_USER=test-b KOTONOHA_LOCAL_PORT=5174 npm run dev:local
```

各利用者の登録・診断を終えた後、Aが作ったローカル招待URLのポートだけを5174へ変えてBで開きます。
これはローカルで別アカウントを模擬する手順です。公開サイトではURLの変更は不要です。
開発サーバーは127.0.0.1だけで待ち受けるため、スマホへ共有するのは公開サイトのURLです。

## 最新の信頼設計：送信を止めるのは修正があるとき

標準チェックはダウンロード不要で、ルールを端末内で実行します。WebGPUや端末内AIが未準備でも普通の文は送信できます。
送信欄に「標準チェックで送信（端末内AI未使用）」と表示します。ルールで修正した場合は警告して入力欄へ戻し、自動送信しません。
修正案を再送すると、その文を最初から確認します。登録本名・連絡先・地名・カード番号・有効期限・CVVに加え、特徴的な勤務先の表現もルールで確認します。
未知の固有名詞や文脈には見落としがあります。

端末内AIは設定から準備して使う任意の追加チェックです。準備成功後にAI追加モードへ切り替わります。
AI追加モードの失敗・判定不明で標準へ黙って切り替えません。送信を止め、再準備または標準への切り替えを案内します。
標準への切り替えは画面操作で行えます。ページ再読み込み後は標準から始まります。
WebGPU対応・空きメモリー・モデル配信通信が必要ですが、検出対象の文章は外部AIに送りません。

外部AIの文章補助は、選択中のチェックを通った文を本人が全文確認してから送ります。
返答も同じチェックを通し、警告付きで入力欄へ戻します。相手へ自動送信しません。
「ちょっとボケる」は、明らかな空想・擬人化を大げさに膨らませ、ツッコミやオチを付けます。
新しい個人情報・実際の予定・約束・暴言・性的表現は追加するよう指示しません。

`trust-review.js` が確認の分岐、`local-findings.mjs` がAI結果の根拠検証と置換を担当します。
サーバーでもルールと登録本名を確認し、個人情報候補を拒否します。`privacyVersion` は互換性管理でありAI実行の証明ではありません。
検出には見落とし・誤検出があり、完全匿名化や情報流出ゼロの保証ではありません。
