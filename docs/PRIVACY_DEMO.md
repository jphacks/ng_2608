# プライバシー保護のデモ手順

本ブランチの機能を、実在する個人情報を入力せずに確認するための手順です。以下は期待する動作であり、実利用者への効果検証の結果ではありません。

## 準備

- [READMEの起動手順](../README.md#起動方法)で起動するか、公開アプリを開きます。
- チャットを画面で試すには、2つの別アカウントで登録・価値観トークを完了し、招待リンクから相互に会話できる状態にします。
- ローカルでの2利用者の認証設定は[開発用README](../web/README.md#別利用者の画面でローカル確認する)を参照してください。
- 最初は標準チェックで試します。端末内AIのモデルや外部AIのキーは、標準のルール処理には不要です。ただし、現在の登録フローを最後まで進めるには外部AIの設定が必要です。
- 送る側と受ける側の両方の画面を開き、候補の表示と実際の受信を区別して確認します。

## 1. 普通の文章を送る

送る側で、次を入力して送信します。

```text
映画を見て、感想を話せたらうれしいです！
```

**期待する動作：** 標準チェックで指摘がなければ、入力した文章が相手に届きます。端末内AIのモデル準備は求められません。外部AIによる文章補助の承認画面も出ません。

## 2. 場所を含む文章を送ろうとする

次は実在する利用者の情報ではなく、検証用の文章です。

```text
渋谷駅の近くに住んでいます。映画が好きです！
```

**期待する動作：** 生活圏の候補を検出し、警告して、次の修正案が入力欄へ戻ります。この操作では相手の受信欄に文章が追加されません。

```text
駅の近くに住んでいます。映画が好きです!
```

修正案を確認して、もう一度送信します。再確認で追加の指摘がなければ、修正後の文章が届きます。趣味の話題が残り、具体的な駅名が送られていないことを確認してください。

## 3. 修正文の編集にも、再確認が入る

前項の警告後、修正案の先頭を再び「渋谷駅」に変更して送信してみます。

**期待する動作：** 編集した文を最初から確認し、再び警告と修正案が出ます。「一度確認した」という理由で、新しく追加した情報がそのまま通ることはありません。

## 4. 端末内AIの追加チェック

対応するWebGPU環境で、設定から端末内AIを準備して追加チェックを有効にします。モデルの取得にはネットワークと空きメモリーが必要です。

固有の店や習慣の記述を含む合成した文章で、追加の指摘が出るかを確認します。モデルの検出は確率的であり、同じ種類の文章を必ず検出する保証はありません。ルールが先に修正した場合は、その操作ではルールの修正案が返ります。

**期待する動作：** AIが修正を提案した場合も、その操作で相手へ送信せず、入力欄へ戻ります。AI追加中に処理失敗・判定不明になった場合も送信しません。標準チェックへの切り替えは本人が設定で行います。

失敗や不正な出力の分岐は、以下の自動テストで再現できます。これは本番モデルの精度を測る試験ではありません。

```sh
# web/ で実行
node --test tests/trust-review.test.mjs
```

## 5. 外部AIの文章補助を使う

外部AIのキーとモデルを設定した状態で、一般的な映画の文章を入力し、「ちょっとボケる」または「会話を広げる」を押します。

**期待する動作：** 選択中のプライバシー確認を通った文章について、外部へ送る全文と目的を確認できます。本人が承認するまで、文章補助の外部送信を行いません。

承認して候補を受け取っても、相手の受信欄にはまだ追加されません。候補は再確認されて入力欄へ戻り、本人が編集・送信します。外部AIを利用する操作と、相手へ送る操作が分かれていることを確認してください。

## 6. 写真の背景変更と公開範囲

自分で公開してよい写真を選び、背景を変更します。「消す」「戻す」・取り消し・拡大・ブラシサイズを試し、確定前に修正できることを確認します。名札・服の文字・残った背景も確認してから「この画像にする」を押します。

登録の選択回答・価値観トークの結果は、公開項目を外したり紹介文を編集したりして、公開直前の確認内容に反映されることを確認します。

## コードで確認できること

```sh
# web/ で実行
npm test
node --test tests/trust-server.test.mjs
```

- [trust-review.test.mjs](../web/tests/trust-review.test.mjs)：修正時の停止、再確認、標準チェック、追加AIの失敗、不正な引用・重なる範囲の処理。
- [trust-server.test.mjs](../web/tests/trust-server.test.mjs)：個人情報候補を外部AIへ渡す前の拒否、原文やキーをエラー応答へ含めない処理、古い入力形式の拒否。
- [情報の境界と残る制約](TRUST_BOUNDARIES.md)：端末・アプリサーバー・外部AI・相手が扱う情報の範囲。
