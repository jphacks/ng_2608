# 検証と困ったとき

コマンドは特記しない限り `web/` で実行します。

## 自動テスト

```sh
npm test
```

現在の構成は85件です。外部APIに実際のリクエストを送らず、ゲートウェイはテスト用応答、保存はメモリー内SQLiteで確認します。

| テスト | 主な対象 |
| --- | --- |
| `tests/community.test.mjs` | 非公開氏名・年収の分離、保存・削除、会話の認可、ブロック、写真メタデータ |
| `tests/gateway.test.mjs` | Origin・認証・入力制約、個人情報の再検出、同意設定、AIエラーと上限、出力検証 |
| `tests/questionnaire.test.mjs` | 14問・6分野、非公開・未回答、相性計算、20歳未満の飲酒回答拒否 |
| `tests/support.test.mjs` | 普通の会話を変えない、氏名・収入・強い言葉の加工、写真の条件付き注意 |

GitHub Actionsの `.github/workflows/test.yml` も、push/PR時にNode.js 24で `npm ci` と `npm test` を実行します。
現在のCIはビルドやブラウザー操作まで実行しません。

## ブラウザーで確認すること

合成した名前・写真・文章で、ローカル環境を使います。

1. 基本情報を保存すると写真へ進む。氏名と公開名を区別し、年収は任意・非公開が初期設定。
2. 写真を選ぶと自動検出する。顔1つ・文字候補なし・検出成功なら警告がなく、候補や検出失敗がある時だけ注意が出る。
3. 写真は登録または後回しにでき、14問へ進む。毎回の3つのチェックはない。
4. 質問で非公開にした回答を相性へ含めず、根拠不足なら数値を出さない。
5. 架空の相手とのチャットで「こんにちは！今日もおつかれさま♡」が文面を保ってモーダルなしで送られる。
6. 架空の駅名・カード番号・登録本名を含む文で警告が出て入力欄へ戻り、相手・外部AIへ送られない。暴言・下ネタは拒否される。
7. モデル未準備でも標準チェックで普通の文章を送れる。任意のAI追加中に失敗した場合は送信を止め、明示的に標準へ切り替えられる。ボケ候補は大げさなコント調で入力欄へ戻り、再送するまでは相手へ届かない。
8. 会話一覧の更新で入力途中の文章が消えない。スマホ幅で下部ナビが本文に重ならない。

単一のローカルプレビューは利用者を1人に固定します。ブラウザーを分けても別利用者にはなりません。
実際の二者間の認可は自動テスト、公開環境の二者間UXは別アカウントで検証する必要があります。

## ビルドとDB

```sh
npm run build
```

Vinext/Cloudflare向けのビルドです。公開サイトへは自動反映されません。
`npm run dev` はフレームワーク用で、初参加者のローカルデモは `npm run dev:local` を使います。

DBを変える時：

```sh
npm run db:generate
```

`db/schema.ts` の変更からSQLを生成し、差分をレビューします。既存の `0000`〜`0002` は編集しません。
移行ファイルを増やすだけではローカルの起動処理が自動追従するとは限りません。`scripts/local-storage.mjs` とテストの初期化も更新してください。
公開DBへの適用は [公開と運用](DEPLOYMENT.md) を参照してください。

## よくあるつまずき

| 状況 | 確認すること |
| --- | --- |
| clone後にアプリがない | `git branch --show-current`。開発ブランチを指定したか |
| `Permission denied (publickey)` | SSHのアカウント設定。取得だけならHTTPS cloneも使える |
| pushが拒否される | リポジトリへの書き込み権限と自分の作業ブランチか |
| `node:sqlite` を読み込めない | `node --version`。Node.js 22.13以降か |
| `ENOENT` / `package.json` がない | `web/` で実行しているか |
| `EADDRINUSE` | 5173で起動中のプレビューがないか。自分の前のプロセスを終了する |
| 保存・送信がOriginエラー | `http://127.0.0.1:5173` で開いているか |
| AI補助が働かない | キー設定後に再起動したか、本人設定を有効にしたか、候補を検出する文か。普通の文ではAIを使わない |
| AIが端末内処理へ戻る | 設定・キー期限・利用枠・通信・出力検証・日次上限の可能性。外部送信記録を確認し、無限に再試行しない |
| 写真の初回処理が遅い | OCR/顔検出モデルを読み込み中か。検出に失敗した場合は注意が出る |
| 写真のモデルがない | `npm run vision:prepare` でアセットを再作成し、生成差分・ライセンスを確認 |
| ローカルの設定が残る | `.sites-runtime` が永続保存先。同じ利用者IDの過去データを再使用している |
| push後も公開サイトが変わらない | GitHub保存とSites公開は別。[公開手順](DEPLOYMENT.md)を確認 |

ローカルの保存先を削除するとローカルデータが失われます。リセット目的で他人の環境や本番DBを消さないでください。
公開サイトの登録削除は実際に関連データを消す操作なので、動作確認のために他人のアカウントで実行しないでください。

`tests/friends.test.mjs` は招待の期限・1人用・同時受諾・別利用者の送受信・NG本文を保存しないことを確認します。

`trust-review.test.mjs` と `trust-server.test.mjs` は、修正を送信許可にしないこと、AI失敗時の停止、カード・地名・本名、AI引用検証、外部送信前の拒否を確認します。
