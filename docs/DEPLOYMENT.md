# 公開と運用

## GitHub保存と公開は別

現在の公開先： https://kotonoha-first-connect-uchida.seira20071004.chatgpt.site/demo/

このリポジトリのGitHub Actionsはテストだけです。**pushやPRのマージだけで公開サイトは更新されません。**
公開版はSitesのソースリポジトリ・保存版・公開処理で管理しています。
GitHubへの書き込み権限を持っていても、このSitesプロジェクトの編集権限や秘密変数へのアクセスを持つとは限りません。

## 設定の扱い

GitHubの `web/.openai/hosting.json` はD1の `DB`、R2の `BUCKET` というバインディング名を示します。
既存サイトを誤って操作・複製しないため、この共同開発用コピーにはサイトを特定する `project_id` を含めていません。
**そのまま公開操作を実行して既存サイトが更新されると考えないでください。** 公開担当者が現在のSitesプロジェクトを確認し、正しいソースへ変更を取り込みます。

| 公開側の設定 | 用途 |
| --- | --- |
| `OPENAI_API_KEY` | サーバー秘密変数。ブラウザー・GitHubに含めない |
| `OPENAI_MODEL` | 現在の公開構成で使用するモデル。実装時は `gpt-4.1-mini` |
| `DB` | D1。SQL移行を伴う保存先 |
| `BUCKET` | R2。加工後写真の保存先 |
| 認証・公開範囲 | Sites側で管理。アプリのプロフィール公開選択とは別 |

この案内を追加した時点のサイト公開範囲はpublicです。変更時に現在の設定を確認してください。
アプリのデータAPIは認証を要求します。共有リンクが見えることと、未認証でデータ操作できることは別です。
既存の公開キーは作成時に7日間の期限を選択しています。キーの値や期限をGitに保存せず、公開担当者が期限・利用枠を管理します。

## 公開担当者の手順

1. レビュー済みのGitHubコミットと現在のSitesソースの差分を確認し、対象の変更だけ取り込む。
2. `npm test`、`npm run build`、必要なブラウザー確認を行う。公開用成果物に秘密ファイルや実利用者のデータを含めない。
3. `db/schema.ts` / `drizzle/` の差分と、対象DBへ適用する移行を確認する。開発用データを本番へコピーしない。
4. Sitesの正しい既存プロジェクトのソースへ、その版をpushする。
5. そのコミットから作った公開用アーカイブを使ってSitesの版を保存し、保存した版を公開する。
6. 公開の成功を確認し、ホーム・登録・相手探しなどの画面を確認する。実データを使う更新・削除を検証目的で行わない。
7. 公開したGitHubコミットとSitesの版をチームへ記録する。

Sites用のビルド・梱包は、その環境に用意されたSitesスキルの手順に従います。
個人のPCにしかない絶対パスは、チーム共通のコマンドとして要求しません。
GitHubからの自動デプロイと、別環境へ移すための一式の運用設定は未整備です。

## 他のホストへ移す場合

このアプリはCloudflare Workers / D1 / R2と、Sitesが渡す認証情報を前提にしています。
一般の静的ホスティングへファイルを置くだけでは、保存・認証・実チャットは動きません。
別のホストでは、認証、DB/R2相当、Originの扱い、秘密変数、移行とアクセス制御を実装・検証してください。
認証ヘッダーを外部クライアントが自由に指定できる構成にしないでください。

## 今後、チームで決めること

- `main` へ統合するタイミング、レビュー担当、公開担当と公開頻度。
- 本人確認・年齢確認、通報を確認して対応する運用。
- データ保存期間、バックアップ・復旧、キー更新、費用と利用上限の管理。
- 検出の見落とし・言い換えの意味のずれを集めるための、本人が同意した検証方法。
- ブラウザー側の自動変換に加えて、直接のAPI送信をどの範囲までサーバーで制限するか。

これらは現在のアプリで完了済みという意味ではありません。
