# スキあらば恋、隙間ないAI

**身元を詳しく伝える前に、「何を大切にする人か」からつながる。**

自分が大切にする価値観を選び、伝える情報を自分で決めながら、会話を通じて相手を知っていくマッチングアプリです。
質問に答えて相手を見つけるところから、マッチング後の会話までを支えます。

[公開デモ](https://kotonoha-first-connect-uchida.seira20071004.chatgpt.site) / [起動手順](docs/GETTING_STARTED.md) / [開発用ソース](web) / [実装の詳細](web/README.md)

> このREADMEは `codex/friends-chat-guard` ブランチの実装を説明します。公開デモの更新状況とは異なる場合があります。現在はプロトタイプであり、実ユーザーの課題をどの程度解決できるかは、これから検証します。

## 解決したい課題

相手と仲良くなりたい。でも、まだ信頼関係ができていない相手に、本名・学校・生活圏まで伝えるのは不安。
プロフィールだけでは、連絡のペースや休日の過ごし方など、一緒に過ごすときの希望も分かりにくい。

想定するのは、**人柄や価値観を知ってから関係を深めたい一方で、身元に関わる情報は慎重に伝えたい18歳以上の利用者**です。
「相手を知ること」と「自分の情報を守ること」を両立できる体験を目指します。

## このプロダクトで大切にしている3つの違い

### 1. 「自分は何を大切にするか」を、相性に反映できる

6分野14問で、連絡や会うペース、休日、理想の関係などの希望を整理します。
各質問では、一致をどれくらい大切にするかも選べます。

- 特に大切
- 普通に大切
- 違っても気にしない

例えば、同じ「休日は家で過ごしたい」という回答でも、「相手も同じだとうれしい人」と「相手は外出好きでも気にしない人」がいます。
回答の一致だけでなく、その人にとっての大切さも表現できる設計です。

公開した回答を相性の根拠にし、未回答・非公開の項目を推測で埋めません。
選択式チェックの後には、外部AIとの3つの場面の対話で希望を言葉にします。結果は本人が確認・編集し、公開する項目を選びます。

### 2. いきなり身元を明かさず、伝える情報を段階的に選べる

最初は表示名と、公開を選んだ価値観から交流を始めます。
氏名は本人用の登録情報として公開プロフィールから分離し、年収は任意・初期設定では非公開です。

写真は端末内で背景や写り込みを加工し、文章は個人情報候補を検出して一般的な表現に整えます。
外部AIの文章補助は「ちょっとボケる」「会話を広げる」を選び、加工済み文章の送信内容を確認して使います。

**伝える情報を選びながら、相手を少しずつ知っていくこと**が狙いです。
これは本人確認や相手の信頼性の保証ではなく、開示する情報を本人が管理するための仕組みです。

### 3. マッチングした後の会話も、相手を知るきっかけにする

チャットでは、やりとりに合わせて「いまの会話相性」を更新します。
プロフィールを見て相手を選ぶだけでなく、実際に話す時間にも目を向ける体験です。

**現在の会話相性は、共通話題・発言のやりとり・前向きな表現などを使うルールベースの参考値です。**
会話の意味を生成AIが理解して価値観の一致を診断する機能ではありません。
今後は、「共通している希望」「違いがある希望」「次に話してみたいこと」を理由付きで示し、本人が解釈を訂正できる可視化へ発展させます。

この3つを、登録から会話まで一つの流れに組み込むことを差別化の軸にしています。競合各社の機能の有無や、追随できない優位性を実証したという主張ではありません。

## 利用の流れ

1. **プロフィール・写真を登録**：表示名と本人用の登録情報を分け、写真の背景・写り込みを確認する。
2. **14問の価値観チェック**：自分の希望と、相手との一致を大切にする度合いを選ぶ。
3. **3問のAI対話**：休日、連絡のペース、希望が分かれた場面について話す。
4. **公開内容を確認**：回答・AIのまとめを確認し、相手に伝える項目を選ぶ。
5. **相手を探して会話**：相互に関心を持った相手と話す。招待リンクで友達と試すこともできる。

写真の登録、AI対話、結果の公開確認が済んだ後に、相手探しを利用できます。

## 実装済みの機能

| 機能 | 現在できること |
| --- | --- |
| 価値観チェック | 6分野14問。質問ごとの重視度と公開範囲を選択できる |
| プロフィールの相性 | 共通して公開している回答と重視度を比較。比較できる回答が7項目・3分野以上ある場合に総合点を表示する |
| AIとの価値観トーク | 固定3問の対話、回答の加工と送信確認、結果の確認・編集・項目ごとの公開に対応する |
| 写真の保護 | 元画像を端末内で処理し、背景変更や写り込みの加工後の画像を保存する |
| チャットの送信補助 | 検出した個人情報候補を加工。外部AIの文章補助は利用者の明示操作と送信確認で使う |
| NG発言の制御 | 検出した暴言・性的な発言をブラウザーとサーバーで拒否する |
| 会話中の参考スコア | 送信済みの直近100件から端末内で更新する。双方の発言がある場合に80点を起点として加点し、80〜98点を表示する |
| 友達との実チャット | 別アカウントの友達を招待し、相手の同意後に送受信する。画面の前面表示中は約2秒ごとに更新する |
| 関係の管理 | ブロック、解除、通報の受付記録に対応する |

プロフィールの相性と、会話中の参考スコアは別の計算です。
現在の会話スコアは高めの数値になりやすい製品上の仮ルールであり、数値だけで「価値観が合う」「相手に好かれている」と判断できるものではありません。
いずれも心理検査や恋愛の成功確率を表しません。

## プライバシーの設計と、現在の限界

| 情報 | 扱い |
| --- | --- |
| 氏名 | 本人用の登録情報としてサーバーへ保存。一般のプロフィールや相手向けの応答へ含めない |
| 年収 | 回答は任意。初期設定は非公開で、相性の採点に使わない |
| 選択式回答・AIのまとめ | 公開する項目を本人が選ぶ。AI診断の最終結果は本人用に保存する |
| 元の写真 | 端末内で処理し、元画像をアップロードしない |
| 加工済み写真・相手との会話 | サイト側に保存し、認証とアクセス制御を通して利用する |
| 外部AIへの入力 | 確認した加工済み文章と、その目的に必要な回答を使う。原文・元写真・登録氏名を付加しない |
| 会話相性の計算 | 端末内で行い、この計算のために会話履歴を外部AIへ送信しない |

自動検出には誤検出・見落としがあります。加工済み文章や写真でも、情報の組み合わせから身元が分かる可能性は残ります。
完全な匿名化、相手の信頼性、被害の防止を保証するものではありません。
年齢は自己申告で、本人確認・年齢確認の審査や、専任の即時通報対応は未提供です。

## フィードバックを受けて、次に検証すること

**機能が動くことと、想定ユーザーの課題を解決できたことは、分けて確認します。**
現段階では実ユーザーによる効果検証の結果を示しておらず、以下を検証計画としています。

| 検証したいこと | 試す方法・確認する指標 | 改善へのつなげ方 |
| --- | --- | --- |
| 質問と重視度で、自分の希望を表現できるか | 質問の分かりにくさ、選びにくい選択肢、重視度を選んだ理由を利用者に聞く | 回答の偏りや不足する選択肢を見直す。相性の表示と本人の納得感のずれを調べ、質問・重みを調整する |
| 個人情報を減らしても、伝えたい意味が残るか | 同意した参加者が確認用の文章・写真で試し、見落とし、誤検出、意味の変化、修正の負担を記録する | 検出ルールと確認導線を改善する。個人情報を出す量を減らすこと自体を利用者へ強制しない |
| 会話中の表示が、相手の理解に役立つか | スコアのみの現行表示と、共通点・違いを理由付きで示す試作を比較し、役立った点と誤解した点を聞く | 点数の高さだけに依存せず、本人が確認できる価値観の可視化へ改善する |
| 公開範囲を自分で選べると感じるか | どこまで公開されると思ったかと、実際の設定が一致しているかを確認する | 公開範囲の説明、確認、変更・解除の操作を改善する |

検証では、参加人数・対象・方法・分かったこと・残った課題を記録します。
自動テストやチーム内デモの結果を、そのまま実ユーザーへの効果の証明として扱いません。
未加工の会話や個人情報を、評価用として無断で収集することもしません。

### 今後追加・改善したいこと

- **価値観の作用を見える形にする**：会話の中の共通する希望や違いを、根拠と一緒に表示する。本人が誤った解釈を訂正できるようにする。
- **公開を段階的に管理する**：交流の段階に合わせて、相手ごとに公開する項目を選ぶ、変更する、解除する操作を検討する。現在の項目ごとの公開設定とは別の拡張として扱う。
- **質問と相性計算を検証し続ける**：実装済みの重視度調整を起点に、利用者の納得感とフィードバックをもとに質問内容・基本重みを見直す。
- **保護機能と運用を検証する**：多様な日本語・写真での検出確認、本人確認・年齢確認、通報後の対応体制を整備する。

## 友達のスマホと試す

1. 各自が別のChatGPTアカウントで公開サイトにログインし、プロフィール・写真・診断・結果確認を完了する。
2. 「さがす」→「友達を招待する」からリンクを共有する。
3. 友達がリンクを開き、「この友達とマッチして話す」に同意する。
4. 「トーク」で送受信する。

招待は24時間有効・1人用です。同じアカウントを2台で使うと、別々の利用者にはなりません。
ローカル開発用の `127.0.0.1` のURLは、そのまま友達のスマホへ共有する用途には使えません。
現時点ではバックグラウンドのプッシュ通知はありません。

詳しくは [スマホ同士で友達と話す](web/README.md#スマホ同士で友達と話す) を参照してください。

## ローカルで起動する

Node.js 22.13以降が必要です。CIでは24を使用しています。

```sh
git clone --branch codex/friends-chat-guard https://github.com/jphacks/ng_2608.git
cd ng_2608/web
npm ci
npm run dev:local
```

表示された `http://127.0.0.1:5173` を開きます。
APIキーなしでも、基本情報・写真・14問と端末内の加工を確認できます。AI診断と、その後の相手探しにはサーバー側のAPI設定が必要です。
各開発者が使用を許可されたキーを `web/.env.local` に設定し、GitHubやチャットへ共有しないでください。

```sh
npm test
```

## 技術構成と主な実装

- **画面**：JavaScript / TypeScript、Vinext、HTML / CSS。スマホ向けの登録・プロフィール・チャット画面。
- **価値観チェック**：[`questionnaire.js`](web/public/demo/questionnaire.js) / [`questionnaire-ui.js`](web/public/demo/questionnaire-ui.js)。14問、重視度、公開範囲、プロフィールの相性計算。
- **登録・AI対話**：[`journey.js`](web/public/demo/journey.js) / [`onboarding.mjs`](web/lib/onboarding.mjs) / [`gateway.mjs`](web/lib/ai/gateway.mjs)。OpenAI Responses APIを利用。
- **会話スコア**：[`conversation-score.js`](web/public/demo/conversation-score.js)。端末内のルールベースで計算。
- **文章と写真の保護**：[`privacy.js`](web/public/demo/privacy.js) / [`chat-policy.js`](web/public/demo/chat-policy.js) / [`photo-detection.js`](web/public/demo/photo-detection.js) / [`background-photo.js`](web/public/demo/background-photo.js)。Tesseract.js・MediaPipeを利用。
- **実チャット・招待**：[`friends.js`](web/public/demo/friends.js) / [`friend-invites.mjs`](web/lib/friend-invites.mjs) / [`community.mjs`](web/lib/community.mjs)。Cloudflare Workers / D1 / R2で保存とアクセス制御。
- **検証**：Node.jsのテストランナーとSQLite。権限、招待の期限・受諾、送受信、NG発言、相性計算などをテスト。

実装上の制約は [web/README.md](web/README.md)、外部コンポーネントの情報は [THIRD_PARTY.md](web/THIRD_PARTY.md) を参照してください。
